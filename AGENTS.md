# sf.nvim

Neovim plugin wrapping the Salesforce `sf` CLI. Lua, tested with mini.test: run `make test` (or `make test_file FILE=tests/test_x.lua`) and `make fmt-check` (stylua, from the nvim devshell; `make fmt` fixes it) before opening a PR. Test dependencies (`deps/`) are pinned by the `*_REV` variables in the `Makefile`; bump one by editing its rev, and `make test` moves existing clones to it. Tests never run a real `sf`: fake it with `child.sf_fake` and the fixtures in `tests/fixtures/sf/`, as described at the top of `tests/helpers.lua`. Re-record those fixtures with `make record-fixtures DEVHUB=sf-nvim-devhub` on a machine logged in to the Dev Hub with JWT (#368). Each run spends one of the Dev Hub's 6 scratch orgs a day: run it once per change and read the scrubbed diff, rather than retrying until it passes.

The help file `doc/sf.txt` (and `doc/tags`) is generated by mini.doc from the `---` comments in `lua/sf/init.lua`, and CI regenerates and commits it on every push to `dev` (`.github/workflows/doc.yml`). PRs edit the `---` comments, never `doc/sf.txt`; run `make doc` to preview the result locally.

## Pace

sf.nvim is a small plugin, and a small bug is cheap: a user or the maintainer files an issue and it gets fixed. Optimise for speed with the least human intervention. Decide rather than ask, and make the tests strong enough to stand in for review: when they pass, merge your own PR into `dev`. Ask the maintainer only for what needs their hands (an org's admin UI, a secret) or what can't be undone.

## Branches

- `dev` is the integration branch. Every PR targets `dev` (`gh pr create --base dev`) and is squash-merged; the PR title must be a conventional commit (`feat: ...`, `fix: ...`), since it becomes the commit on `dev`.
- `main` is what users install. It only moves by fast-forwarding to `dev` (`git push origin origin/dev:main`) once the maintainer has tried `dev` by hand. Never open a PR against `main` and never commit to it directly; hotfixes go through `dev` too, or the fast-forward breaks.
- GitHub closes an issue from `Closes #N` only when the commit reaches `main`. After merging a PR into `dev`, close its issue by hand with a comment naming the PR, or the tickets it blocks stay blocked. issue-loop (configured in `.issue-loop.conf`) does this itself.
